# Lead Form — Design & Copy

หัวใจของหน้านี้ ทุกอย่างที่เหลือมีอยู่เพื่อพาคนมาถึงฟอร์มนี้

---

## กฎข้อเดียวที่สำคัญที่สุด

**ทุกช่องมีต้นทุน** — แต่ละช่องที่เพิ่มเข้ามา conversion ลดลง ถามเฉพาะสิ่งที่ต้องใช้ *วันนี้*
อย่างอื่นไปถามทีหลัง (ในอีเมล, ตอนโทรกลับ, ตอนมาถึงหน้าร้าน)

| ช่อง | เก็บไหม | เหตุผล |
|---|---|---|
| ชื่อ (ช่องเดียว ไม่แยก first/last) | ✅ | ใช้เรียกในอีเมล/ตอนโทร |
| Email | ✅ | key ที่ใช้ dedupe contact ใน HubSpot |
| เบอร์โทร | ✅ | ธุรกิจไทยปิดการขายทางโทร/LINE |
| สาขาที่สนใจ | ✅ | routing + เป็น deal property |
| แพ็กเกจ | ✅ | ต้องใช้ตั้งราคา checkout (ส่งเป็น `sku`) |
| อายุ / เพศ / อาชีพ / "รู้จักเราจากไหน" | ❌ | ถามทีหลังได้ ตอนนี้มันแค่ทำให้คนปิดหน้า |
| ข้อความเพิ่มเติม (textarea) | ❌ | ทำให้ฟอร์มดูยาว คนกรอกน้อยลงมาก |

**5 ช่อง คือเพดาน** ของหน้า salepage ที่เก็บ lead แล้วต่อการจ่ายเงินทันที

---

## Layout

- **คอลัมน์เดียว** เสมอ (2 คอลัมน์ทำให้คนอ่านข้าม)
- **Label อยู่ด้านบน input** ไม่ใช้ placeholder แทน label (placeholder หายตอนพิมพ์ = คนลืมว่ากรอกอะไร)
- placeholder ใช้เป็น *ตัวอย่าง* เท่านั้น: `เช่น 0812345678`
- input สูง ≥48px · font-size ≥16px (ถ้าเล็กกว่านี้ iOS จะ zoom เอง)
- เรียงจากง่ายไปยาก: ชื่อ → email → เบอร์ → สาขา (select) → แพ็กเกจ (การ์ดเลือกได้)
- ถ้าเขาเลือกแพ็กเกจจากตารางราคามาแล้ว ให้ **pre-select** ช่องแพ็กเกจไว้เลย

## Progressive commitment

ถ้าต้องถามมากกว่า 5 ช่องจริงๆ ให้แบ่ง 2 ขั้น: ขั้นแรกถามแค่ email
(คนที่กรอกไปแล้วมีแนวโน้มกรอกต่อให้จบ — sunk cost) แต่ในคลาสนี้เรา **ไม่ต้องใช้** เพราะ 5 ช่องพอ

## Validation & error

- **inline validation ตอน blur** ไม่ใช่ตอนกดส่ง — บอกทีละช่องว่าอะไรไม่ผ่าน
- ห้ามล้างค่าที่กรอกไว้เมื่อ error
- error message ต้องบอก **วิธีแก้** ไม่ใช่แค่บอกว่าผิด:

| กรณี | ข้อความ |
|---|---|
| email ว่าง | "ใส่อีเมลด้วยนะ เราจะส่งรายละเอียดการจองไปให้" |
| email รูปแบบผิด | "อีเมลนี้ดูไม่ถูกต้อง เช็คตัวสะกดอีกครั้งได้ไหม" |
| เบอร์ผิด | "เบอร์มือถือ 10 หลัก เช่น 0812345678" |
| ยังไม่เลือกสาขา | "เลือกสาขาที่สะดวกก่อนนะ" |
| server error | "ระบบมีปัญหาชั่วคราว กดส่งอีกครั้ง หรือทัก LINE @glowsociety ได้เลย" |

- ปุ่มตอนกำลังส่ง: disable + เปลี่ยนข้อความเป็น "กำลังจองที่นั่ง…" (กันกดซ้ำ = deal ซ้ำ)

## หลังส่งสำเร็จ

1. ยิง `generate_lead` (GA4) + `Lead` (Pixel) พร้อม `value`, `currency`, `sku`, `deal_id`
2. แสดง state สำเร็จทันที ไม่ต้องรอ redirect: "จองที่นั่งไว้แล้ว ✓ กำลังพาไปหน้าชำระเงิน…"
3. เรียก `/api/checkout` แล้ว redirect ไป Stripe
4. ถ้า checkout พลาด **lead ต้องไม่หาย** — บอกว่า "เราเก็บข้อมูลไว้แล้ว ทีมงานจะติดต่อกลับ"
   (lead อยู่ใน HubSpot แล้วตั้งแต่ขั้นที่ 1 — นี่คือเหตุผลที่แยก 2 step)

## Trust ข้างฟอร์ม

ใส่ 3 อย่างนี้ใกล้ปุ่ม ทุกครั้ง:
- **ทำอะไรกับข้อมูล**: "ใช้ติดต่อเรื่องการจองเท่านั้น ไม่ส่งต่อให้ใคร"
- **guarantee**: "รอบแรกไม่ประทับใจ คืนเงินเต็ม"
- **ทางเลือกที่ไม่ต้องจ่ายตอนนี้**: "อยากถามก่อน? ทัก LINE @glowsociety"

## Accessibility

- ทุก input มี `<label for>` ผูกจริง
- error ผูกด้วย `aria-describedby` + `aria-invalid="true"`
- ปุ่ม submit เป็น `<button type="submit">` ไม่ใช่ `<div onclick>`
- ฟอร์มใช้งานได้ด้วยคีย์บอร์ดทั้งหมด · focus ring มองเห็นชัด
